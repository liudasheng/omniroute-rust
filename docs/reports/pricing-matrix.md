## 一、口径（三个不同分母，勿混）

| 口径 | 含义 | 来源 |
|---|---|---|
| **额度美元 budget** | 每模型每月的预算上限，按该模型单价折算消耗 | 官方表 A/B（Go 与 Go Plus 各一列） |
| **token 单价** | input / output / cache_read 的 $/1M | 官方表 A；models.dev 同值 |
| **额度百分比** | 整档 rolling/weekly/monthly 已用比例，**不分模型** | `GET /inference/go/v1/usage` |

官方窗口规则：5 小时 = 月额度 20%；周 = 50%；月 = 100%。
故「性价比」的正确度量是 **额度产出 = 月额度美元 ÷ 每请求成本**，即该模型一个月的预算能换多少次调用、或多少 M token。

**关键发现**：网关确实抓取 models.dev 快照（`~/.omniroute-rust/model-catalog.json`，8,828 行，`fetched_at_ms=1792231488439`），
但落盘行只有 `provider / model / context_window / max_output_tokens / modalities` 五列——
**单价在入库时被丢弃**（`src/model_catalog.rs:363-371` 的 `cost_free()` 只把它折算成「是否免费」）。
即价格数据「已经到手却被扔掉」，这是路由侧拿不到价格的第一道断点。

## 七、月额度美元无法从上游获得

models.dev 全库（232 个 provider）**无任何月度额度字段**；`GET /inference/go/v1/usage` 只给整档百分比。
实测 2026-10-17 21:15 CST：rolling 0%（重置 14:19Z）/ weekly 62%（重置 10-19T00:00Z）/ monthly 31%（重置 11-15T07:26Z）。
故「每模型月额度美元」只能来自官方文档表，须以本地静态表维护并随文档变更复核。
